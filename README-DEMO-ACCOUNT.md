# EduTwin — интеграция демонстрационных личных кабинетов

Весь исходный сайт EduTwin сохранён. Основные файлы интеграции:

- `index.html` — прежняя главная страница, теперь кнопка «Войти» открывает `account.html`; после входа она называется «Личный кабинет».
- `account.html` — новый экран входа с выбором демонстрационного аккаунта и личными кабинетами всех ролей.
- `register.html` — прежний дизайн регистрации, теперь создаёт аккаунт и сразу открывает кабинет нового студента.
- `assets/js/edutwin-auth.js` — общий демонстрационный список аккаунтов, проверка пароля, регистрация, сохранение сеанса и управление правами.
- `scripts/build-static.js` — обновлённая сборка с включением `account.html`.

## Как посмотреть

1. Распакуйте весь ZIP целиком, не извлекайте из него один HTML.
2. Откройте папку в VS Code.
3. Запустите **Live Server** на `index.html` и на главной нажмите **«Войти»**.
4. Для трёх подготовленных аккаунтов используйте согласованные демонстрационные пароли. При нажатии карточки аккаунта заполняется только поле Email.
5. Для проверки регистрации откройте ссылку «Зарегистрироваться» на экране входа. Созданный аккаунт получает роль «Студент», режим «Только просмотр» и не добавляется к официальным 25 студентам.
6. Чтобы выдать дополнительные права, войдите в аккаунт администратора и откройте **«Пользователи»**. Там можно выдавать/отзывать полный доступ, а также назначать преподавателя зарегистрированному пользователю.
7. Работы дополнительных студентов с полным доступом находятся у преподавателя внутри каждого задания, во вкладке **«Дополнительные студенты»**. Ежедневный журнал остаётся на 25 студентов.
8. Кнопка выхода в кабинете возвращает на главную страницу и завершает сеанс. Перезагрузка страницы не завершает сеанс.

Для штатной сборки исходного проекта можно выполнить `npm ci`, затем `npm run build` и `npm run preview` (после настройки среды в соответствии с основным `README.md`).

## Важно

Эта система аккаунтов предназначена **только для локальной демонстрации**. Сведения об аккаунтах и сессии хранятся в `localStorage` данного браузера, а подготовленные пароли присутствуют в клиентском JavaScript. **Это не защищённая серверная авторизация**: доступ к данным и проверку полномочий можно обойти средствами разработчика браузера. Не используйте здесь настоящие пароли или личные данные, не разворачивайте такой режим как публичный сервис. Для реального запуска потребуется сервер, защита паролей и серверная проверка полномочий.

Обновлённый `account.html` по-прежнему использует Tailwind CDN и Google Fonts; для полного оформления интерфейса необходим интернет.

Существующие AI-функции, видео, расписание и прочие части проекта не перерабатывались. Для работы AI-генерации сохраняются прежние требования к среде и ключам из исходного `README.md`.
